# Quickstart & Validation Guide: Agentic Academy MVP

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md)

This guide describes how to run the MVP locally and the end-to-end scenarios that prove each user
story works. Commands refer to the structure in [plan.md](./plan.md#project-structure); they become
runnable as the corresponding tasks are implemented.

## Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Linux x86_64 (or macOS for everything except the secure runner) | — | gVisor only runs on Linux |
| Docker Engine + Compose v2 | Engine ≥ 27 | |
| gVisor `runsc` | latest release | Install from gvisor.dev, then `sudo runsc install && sudo systemctl restart docker`; verify with `docker run --rm --runtime=runsc hello-world` |
| Python + `uv` | 3.13 | backend, runner, content CLI |
| Node.js + `pnpm` | 24 LTS | frontend |
| Playwright browsers | bundled with `@playwright/test` | `pnpm --dir frontend exec playwright install --with-deps chromium` |

## Environment variables

Copy `.env.example` to `.env`. Development defaults need no real secrets.

| Variable | Used by | Dev default | Production rule |
|----------|---------|-------------|-----------------|
| `APP_ENV` | api, runner | `development` | `production` enables all guards below |
| `DATABASE_URL` | api | `postgresql+psycopg://academy:academy@localhost:5432/academy` | API role (full schema access) |
| `RUNNER_DATABASE_URL` | runner | `postgresql+psycopg://academy_runner:runner@localhost:5432/academy` | Role limited to the runner functions (runner protocol §1) |
| `RUNNER_DB_PASSWORD` | migrations (environment or `.env`) | `runner` | set out of band; the migration enables login for `academy_runner` only when provided |
| `SESSION_SECRET` | api | random value generated by `make dev-secrets` | ≥ 32 random bytes, from the secret store |
| `COOKIE_SECURE` | api | `true` (browsers treat `localhost` as secure) | must be `true` |
| `PUBLIC_BASE_URL` | api (email links) | `http://localhost:5173` | `https://…` |
| `EMAIL_BACKEND` | api | `smtp` to Mailpit (`SMTP_HOST=localhost`, `SMTP_PORT=1025`) | `smtp` with real credentials |
| `CONTENT_DIR` | api, runner | `./dist/content` | read-only mount; never contains reference solutions |
| `RUNNER_RUNTIME` | runner | `runsc` | must be `runsc` |
| `RUNNER_SANDBOX_IMAGE` | runner | `academy-sandbox:dev` | pinned digest `academy-sandbox@sha256:…` |
| `RUNNER_CONCURRENCY` | runner | `2` | sized by load (research R10) |
| `RUNNER_OUT_DIR` | runner | `./.runner-out` (plain directory) | a fixed-size tmpfs on the runner host, size = concurrency × 2 MB (runner protocol §3) |
| `RATE_LIMIT_ENABLED` | api | `true` | must be `true` |

**Development-only security exceptions** (each refused at start-up when `APP_ENV=production`, and
logged as a warning otherwise):

- `RUNNER_RUNTIME=runc` — plain containers for machines without gVisor (e.g. macOS). Sandbox
  security results are not valid under this setting.
- `RUNNER_SANDBOX_IMAGE` without a digest.
- `RUNNER_OUT_DIR` not on a tmpfs (the runner checks the mount type at start-up).
- `EMAIL_BACKEND=console` — prints verification and reset links to the API log.
- `RATE_LIMIT_ENABLED=false` — only for load tests.

## Setup from a clean environment

```bash
cp .env.example .env
make dev-secrets                              # writes a random SESSION_SECRET into .env
docker compose up -d --wait db mailpit        # PostgreSQL 17 + local mail catcher
uv sync --project backend
uv sync --project runner
uv run --project backend alembic -c backend/alembic.ini upgrade head # creates schema, runner role and runner functions
uv run --project backend academy content validate
uv run --project backend academy content build --lang en --out dist/content
docker build -t academy-sandbox:dev runner/sandbox-image   # behind a TLS-intercepting proxy add: --secret id=pip_ca,src=<ca-bundle.crt>
sudo mkdir -p /var/lib/academy-runner/out && sudo mount -t tmpfs -o size=8m,mode=0700 tmpfs /var/lib/academy-runner/out   # RUNNER_OUT_DIR
pnpm --dir frontend install
pnpm --dir frontend generate:api              # client from contracts/openapi.yaml; CI fails on drift
uv run --project backend academy dev seed     # optional: verified demo learner demo@example.com / demo-password-123 (--reset recreates it)
```

## Run

Option A — everything in containers:

```bash
docker compose up --build api runner web
```

Option B — processes on the host (faster reloads):

```bash
CHALLENGES_ENABLED=true uv run --project backend uvicorn academy.main:create_app --factory --reload --port 8000
RUNNER_OUT_DIR=/var/lib/academy-runner/out uv run --project runner academy-runner   # RUNNER_RUNTIME=runc on machines without gVisor (development only)
pnpm --dir frontend dev
```

- Web: http://localhost:5173 (Vite proxies `/api` to `:8000`, so cookies are same-origin).
- API docs: http://localhost:8000/api/v1/docs.
- Mailpit (verification and reset emails): http://localhost:8025.
- Health: `GET /api/v1/health` reports database, content bundle version and runner availability
  (a worker heartbeat newer than 30 s).

The runner needs access to the Docker daemon (`/var/run/docker.sock`) in both options; this is why
it runs only on a dedicated host in production (runner protocol §0).

## Automated checks

| Check | Command | Proves |
|-------|---------|--------|
| Content validation | `uv run --project backend academy content validate` | FR-044, FR-048–FR-050 |
| Backend unit + integration | `uv run --project backend pytest` | progress rules, scoring, auth |
| API contract | `uv run --project backend pytest tests/contract` | API matches [contracts/openapi.yaml](./contracts/openapi.yaml) |
| Runner unit (lease, fencing, result validation) | `uv run --project runner pytest tests/unit` | runner protocol §1, §5, §6 |
| Sandbox security suite | `uv run --project runner pytest tests/security` (requires `RUNNER_RUNTIME=runsc`) | FR-022a, SC-011 |
| Frontend unit | `pnpm --dir frontend test` | components, i18n |
| End-to-end + accessibility | `pnpm --dir frontend e2e` (starts API, Vite and the runner itself; set `RUNNER_RUNTIME=runc RUNNER_OUT_DIR=/var/lib/academy-runner/out` without gVisor) | user stories below, NFR-001, SC-007, SC-008 |
| Performance | `pnpm --dir frontend exec playwright test perf --project=desktop` | NFR-003 |
| Load | `uv run --project backend python runner/tests/load/submit_burst.py --n 10` | NFR-006a, SC-012 |

## Validation scenarios (map to spec user stories)

### V1 — Study a module (US1)
1. Open `/` signed out → introductory path visible with level, objectives, prerequisites,
   estimated effort; planned paths marked "not yet available" (US6).
2. Sign up, open the verification link from Mailpit, sign in.
3. Open Module 1 → objectives, entry prerequisites self-assessment, lessons, highlighted code with
   copy button, diagram with text alternative, maturity labels, references, prev/next navigation.
4. Resize to 360 px → no horizontal page scroll; code blocks scroll internally (NFR-002).
**Expected**: all elements present; axe reports no critical violations.

### V2 — Knowledge check (US2)
1. Start Module 1 check → threshold (70%) and objectives shown.
2. Answer with 2 deliberate mistakes → each answer shows correct/incorrect + explanation + lesson link.
3. Submit with < 70% → "not passed", weak objectives listed; retry; submit ≥ 70% → passed; best
   score retained.
4. Disconnect network before submitting, reconnect, submit → single result recorded.

### V3 — Dashboard & persistence (US3)
1. After V2, sign out, sign in from a different browser profile → dashboard shows module "in
   progress" (challenge pending), competencies not yet demonstrated, "continue" to the last lesson.
2. Competency view lists each competency with level, status and evidence.

### V4 — Challenge (US4)
1. Open Module 1 challenge → scenario, problem, expected outcome, instructions, criteria, hints.
2. Reveal one hint → hint count = 1.
3. Run visible tests on starter code → failing criteria with messages.
4. Submit an infinite loop → `stopped (timeout)` within limit; submit code opening a socket →
   `stopped (forbidden_operation)`; submit code that lists the file system → no reference solution
   or other learner's files are present; replace the test files in the submission → the runner
   still uses the bundle's tests; platform unaffected.
5. Submit a correct solution → all mandatory criteria met; module completed; competencies
   demonstrated; reference explanation shown; previous submissions reviewable.
**Expected**: 95% of results within 30 s (measured with the load script `runner/tests/load`).

### V5 — Laboratory (US5)
1. Open scenario "research agent with tools" → task, tools with permissions, pattern, objective.
2. Step forward/back; each element labeled by kind; decision summaries labeled
   "educational explanation"; state shown per element.
3. Compare "fixed workflow" vs "agent loop" → counts and unique elements highlighted.
4. Open the prompt-injection variant → failing element highlighted with risk and mitigation.
5. Reach the destructive action → approval prompt; choose reject → rejected branch replayed.
**Expected**: no network calls to model providers (verify in browser network panel).

### V6 — Content governance (US7)
1. Change a question without bumping `version` → `content validate` fails with a clear message.
2. Bump version, mark an example deprecated → notice visible in the lesson; learners who passed the
   previous version keep their demonstrated competency.
3. Add a module prerequisite that creates a cycle → validation fails.

### V7 — Account lifecycle & resilience
1. Password reset flow via Mailpit → all sessions revoked.
2. Let the session expire while editing challenge code → after sign-in, code is restored.
3. Stop the runner → within 30 s, submitting shows a clear "evaluation unavailable" state and the
   code stays in the editor, while lessons, checks and dashboard keep working (SC-008).
4. Kill the runner while a submission is running → after the 60 s lease expires another worker
   re-runs it; after 3 infrastructure failures it shows `error` and does not count as an attempt.
5. Delete account → confirmation required; sign-in no longer possible; data removed.
